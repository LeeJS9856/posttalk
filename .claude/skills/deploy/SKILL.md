# 배포 절차

## 1. 배포 전 점검

순서대로 돌린다. 하나라도 실패하면 멈춘다.

```bash
npm run lint
npm run build
```

빌드 산출물 크기를 확인한다. 전시장 와이파이가 느릴 수 있으므로 초기 로딩이 커지면 체험 시작이 늦어진다.

## 2. 환경 변수

Vercel 프로젝트 설정에 들어가 있어야 하는 값.

| 키 | 용도 |
| --- | --- |
| `VITE_API_BASE_URL` | 백엔드 주소 |

`.env`는 저장소에 올리지 않는다. 값이 바뀌면 Vercel 대시보드에서 바꾸고 재배포한다.

## 3. 배포

`main` 브랜치에 머지하면 Vercel이 자동 배포한다. 미리보기 배포는 PR을 열면 생긴다.

전시 중 급한 수정은 **PR 없이 직접 푸시하지 않는다.** 되돌릴 지점을 잃는다. 급해도 브랜치를 파고 머지한다.

## 4. 전시 기기 설정

배포가 끝나면 거치 기기에서 한 번씩 확인한다.

1. 크롬으로 배포 주소 접속
2. 홈 화면에 추가 (PWA 설치) — 주소창 없이 실행되는지 확인
3. 운영자 계정으로 로그인
4. 전시 음식에 맞춘 정보 템플릿 저장
5. 가게 사진·영상을 기기 갤러리에 미리 저장
6. 기기 설정에서 화면 자동 꺼짐 끄기
7. 앱 고정(화면 고정) 켜기

## 5. 전시 중 수정

PWA는 서비스 워커가 이전 버전을 캐시한다. 배포 후 기기에서 바뀌지 않으면 앱을 완전히 닫았다 다시 연다.

## 하지 말 것

- 전시 당일 아침에 의존성을 새로 추가하지 않는다.
- 빌드가 깨진 채로 머지하지 않는다. 자동 배포라 바로 전시에 올라간다.
