# 촬영·미디어 규칙

전시 기기에서 카메라 프리뷰와 녹화가 동시에 돌아간다. 이 구간의 성능 선택이 체험 성패를 가른다.

## 기기에 저장하지 않는다

촬영한 사진·영상은 **메모리에만 둔다.** `<input type="file" capture>`로 기기 카메라 앱을 띄우면 촬영물이 갤러리에 저장되어, 공용 기기의 갤러리가 체험 횟수만큼 오염된다. 그러면 사전에 넣어둔 가게 사진을 관람객이 찾지 못한다.

`getUserMedia`로 앱 안에서 직접 촬영한다. 갤러리 선택은 `capture` 속성 없는 `<input type="file">`로 한다.

장면마다 촬영과 갤러리 중 무엇으로 올릴지 관람객이 고른다. 목록에서 슬롯을 누르면 바텀시트로 묻고, 고른 경로는 `?source=camera|gallery`로 넘긴다. 가게 장면은 갤러리를 권하지만 강제하지 않는다.

## 미리보기 URL 정리

`URL.createObjectURL`로 만든 주소는 교체·초기화 시점에 반드시 `revokeObjectURL` 한다. 전시 내내 같은 탭이 떠 있으므로 누수가 그대로 쌓인다.

## 장면 단위

촬영은 장면 순서대로 진행한다. 장면 수는 템플릿의 장면 구성과 입력한 메뉴 수로 정해지며, 상수로 관리한다.
촬영한 재료는 그 자리에서 `sceneIndex`와 메뉴에 연결한다. 나중에 사진과 메뉴를 맞추는 단계를 만들지 않는다.

## 성능

이 경로에서는 WebGL·셰이더·3D·무거운 CSS 필터를 쓰지 않는다. 보급형 안드로이드에서 프레임이 떨어지거나 발열로 녹화가 끊긴다.
애니메이션이 필요하면 `transform`과 `opacity`만 쓴다.

## 하지 말 것

- 촬영 중 화면에 하단 메뉴를 노출하지 않는다. 생성 중 이탈하면 결과물을 놓친다.
- 영상 길이·비율 검증을 생략하지 않는다. 규격에 안 맞는 재료는 생성 단계에서 실패한다.
