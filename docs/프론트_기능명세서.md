# 프론트 기능명세서

PostTalk 프론트엔드 기능명세. 2026 CO-SHOW 전시용.

## 1. 공통 규칙

### 1.1 인증

- 로그인은 프론트엔드에서 고정 계정(`1234` / `1234`)을 검증한다.
- 인증 통과 후 모든 API 요청에 `user_id = 1`을 전달한다.
- 세션은 `localStorage`에 보관하며 만료시키지 않는다. 전시 중 세션이 끊기면 관람객이 로그인 화면에서 막히기 때문이다.

### 1.2 상태 관리

- 제작 흐름의 중간 산출물(콘셉트, 가게·메뉴 정보, 촬영 재료, 자막)은 Context 한 곳에서 관리한다.
- 촬영 파일은 메모리에만 보관하고 기기 저장소에 쓰지 않는다.
- 재료가 없는 상태로 제작 중간 화면에 진입하면 홈으로 보낸다. 새로고침·앱 재시작 시 복구는 지원하지 않는다.

### 1.3 화면 이동

- 각 단계는 독립 URL로 분리하고, 뒤로 가도 입력값과 재료를 유지한다.
- 제작 흐름 화면에는 하단 메뉴를 노출하지 않는다. 생성 중 이탈로 결과물을 놓치는 것을 막는다.
- 생성 대기에서 광고 상세로 이동할 때는 히스토리를 대체(`replace`)해 뒤로 가도 생성이 다시 실행되지 않게 한다.

### 1.4 오류 처리

- 네트워크·서버 오류는 생활 한국어로 안내하고 재시도 수단을 제공한다.
- 요청 진행 중에는 해당 버튼을 비활성화해 중복 요청을 막는다.
- 구현하지 않은 메뉴(마이페이지·설정)는 진입 대신 안내 문구를 노출한다.

## 3. 화면별 명세

### SC-00 로그인

| 항목 | 내용 |
| --- | --- |
| 구성 | 아이디 입력, 비밀번호 입력, 로그인 버튼 |
| 동작 | 고정 계정과 일치하면 세션을 저장하고 홈으로 이동 |
| 예외 | 불일치 시 입력란 아래 안내 노출 |
| 데이터 | 없음 (프론트 검증) |

전시 운영상 운영자가 미리 로그인해두므로 관람객은 이 화면을 보지 않는다. 전시 빌드에서는 입력란에 값을 미리 채워 둔다.

### SC-01 홈

| 항목 | 내용 |
| --- | --- |
| 구성 | 서비스 소개 문구, 광고 만들기 버튼, 최근 만든 광고 목록, 하단 메뉴, 설정 진입 |
| 동작 | 광고 만들기 → SC-02 / 썸네일 → SC-08 / 전체보기 → SC-09 |
| 예외 | 목록이 비어 있으면 안내 문구 노출 |
| 필요 데이터 | 최근 광고 4건: `adId`, 형식, 썸네일 URL, 메뉴명 또는 제목, 게시 상태 |

광고 만들기는 화면에서 가장 큰 영역을 차지한다. 마이페이지·설정은 안내 문구만 노출한다.

### SC-02 콘셉트 선택

| 항목 | 내용 |
| --- | --- |
| 구성 | 광고 형식 선택(카드뉴스·릴스), 형식별 결과물 샘플, 콘셉트 3종 선택과 콘셉트별 예시 |
| 동작 | 형식과 콘셉트를 고르고 다음 → SC-03 |
| 예외 | 형식·콘셉트 미선택 시 다음 버튼 비활성 |
| 필요 데이터 | 없음 (샘플 이미지는 앱에 포함) |

콘셉트 예시 이미지는 카드뉴스 기준으로 제공하고, 결과물 샘플은 형식별로 각각 제공한다.

콘셉트마다 대응하는 릴스 템플릿이 다르고, 템플릿에 따라 자막을 사용하지 않는 경우가 있다. 프론트는 템플릿 장면 구성 정의에 자막 사용 여부를 함께 두고, 이후 단계의 분기에 사용한다.

### SC-03 정보 입력

| 항목 | 내용 |
| --- | --- |
| 구성 | 템플릿 불러오기 목록, 가게 설명 입력, 메뉴 목록(최대 3개, 이름과 설명), 템플릿 저장 선택, 다음 버튼 |
| 동작 | 템플릿 선택 시 아래 입력값을 채움 / 메뉴 추가·삭제 / 다음 → 대본 선행 생성 요청 후 SC-04 |
| 예외 | 가게 설명과 메뉴 1개 이상이 없으면 다음 버튼 비활성, 메뉴 3개 도달 시 추가 버튼 비활성 |
| 필요 데이터 | 템플릿 목록 조회, 템플릿 저장, 대본 생성 요청 |

- 가게 이름·주소는 회원 정보에 있으므로 입력받지 않는다.
- 템플릿 저장은 기본값이 해제이며, 불러온 템플릿을 수정해도 원본을 덮어쓰지 않는다.
- 메뉴 수에 따라 촬영 장면 수가 달라지므로 예상 촬영 횟수를 함께 안내한다.
- 다음을 누르는 시점에 대본 생성을 선요청하고 응답을 기다리지 않는다. 자막을 사용하지 않는 템플릿이면 요청하지 않는다.

### SC-04 재료 확보

| 항목 | 내용 |
| --- | --- |
| 구성 | 진행 표시(현재 장면 / 전체), 장면 안내 문구, 구도 샘플 이미지, 촬영 버튼, 갤러리 선택 버튼 |
| 동작 | 촬영 또는 갤러리 선택 후 다음 장면으로 이동, 마지막 장면 완료 시 SC-05 |
| 예외 | 카메라 권한 거부 시 안내와 갤러리 선택 유도, 영상 길이 미달 시 재촬영 요청 |
| 필요 데이터 | 없음 (재료는 SC-07에서 일괄 업로드) |

- 장면 수와 구성은 템플릿 장면 구성 정의에 메뉴 수를 적용해 결정한다.
- 음식 장면은 촬영, 가게 장면은 갤러리 선택으로 받는다.
- 구도 샘플은 메뉴 종류가 아니라 구도만 보여주는 공통 이미지를 사용한다.
- 영상은 9:16 세로 규격으로 변환해 보관한다.

### SC-05 재료 확인

| 항목 | 내용 |
| --- | --- |
| 구성 | 장면별 재료 미리보기 목록, 장면별 재촬영 버튼, 다음 버튼 |
| 동작 | 재촬영 → 해당 장면의 SC-04로 이동 / 다음 → 자막 있는 릴스 템플릿은 SC-06, 그 외는 SC-07, 카드뉴스는 SC-07 |
| 예외 | 비어 있는 장면이 있으면 해당 장면으로 유도 |
| 필요 데이터 | 없음 |

### SC-06 자막 확인 (릴스 전용)

| 항목 | 내용 |
| --- | --- |
| 구성 | 장면별 항목(촬영 클립 썸네일, 장면 대상 표시, 자막 입력, 글자 수 표시), 영상 만들기 버튼 |
| 동작 | 자막 수정 후 영상 만들기 → SC-07 |
| 예외 | 대본이 아직 도착하지 않았으면 로딩 노출, 실패 시 재요청 버튼 |
| 필요 데이터 | 대본 생성 결과: 장면 번호, 장면 대상, 자막 문안 |

- 자막은 TTS 내레이션과 같은 텍스트를 사용한다.
- 장면당 글자 수를 제한한다.
- 장면 순서는 템플릿이 고정하므로 변경을 제공하지 않는다.
- 배경음악은 사용하지 않는다.
- 자막을 사용하지 않는 릴스 템플릿과 카드뉴스는 이 화면을 거치지 않고 SC-05에서 SC-07로 이동한다.

### SC-07 생성 대기

| 항목 | 내용 |
| --- | --- |
| 구성 | 진행 상태 표시, 안내 문구 |
| 동작 | 재료 업로드 → 생성 요청 → 상태 폴링 → 완료 시 SC-08로 `replace` 이동 |
| 예외 | 생성 실패 시 안내와 재시도, 업로드 실패 시 해당 재료 재전송 |
| 필요 데이터 | 재료 업로드, 생성 요청, 생성 상태 조회 |

생성 상태 응답에 단계 정보가 포함되면 단계별 문구를 표시하고, 없으면 진행 표시만 노출한다.

### SC-08 광고 상세

| 항목 | 내용 |
| --- | --- |
| 구성 | 게시 상태 배지, 결과물 미리보기(카드뉴스 넘겨보기 / 릴스 재생), 캡션 입력, 동작 버튼 |
| 동작 | 캡션 수정 / 인스타그램에 올리기 / 이미지 저장 / 나가기 |
| 예외 | 게시 실패 시 안내와 다시 시도, 게시 완료 후에는 캡션을 읽기 전용으로 전환 |
| 필요 데이터 | 광고 상세 조회, 캡션 수정, 게시 요청 |

진입 경로와 게시 상태에 따라 동작 버튼이 달라진다.

| 상황 | 상태 배지 | 버튼 |
| --- | --- | --- |
| 제작 직후 | 게시 전 | 인스타그램에 올리기 / 이미지 저장 / 홈으로 |
| 보관함, 미게시 | 게시 전 | 이미지 저장 / 뒤로 |
| 보관함, 게시됨 | 게시됨 | 인스타그램에서 보기 / 이미지 저장 / 뒤로 |
| 게시 실패 | 게시 실패 | 다시 시도 / 이미지 저장 / 홈으로 |

- 공용 계정이므로 보관함에서 진입한 미게시 광고에는 게시 버튼을 노출하지 않는다. 다른 관람객의 광고를 게시하는 것을 막는다.
- 카드뉴스 저장은 현재 보고 있는 장을 저장한다. 모바일 브라우저가 다중 파일 동시 저장을 제한한다.
- 캡션은 인스타그램 제한(본문 2,200자, 해시태그 30개)을 넘지 않도록 입력 단계에서 막는다.
- 홈으로 이동 시 제작 흐름의 입력값을 비운다.

### SC-09 보관함

| 항목 | 내용 |
| --- | --- |
| 구성 | 형식 필터, 게시 상태 필터, 광고 목록, 광고 만들기 버튼 |
| 동작 | 항목 선택 → SC-08 / 필터 변경 시 목록 재조회 / 만들기 → SC-02 |
| 예외 | 목록이 비어 있을 때와 필터 결과가 없을 때 각각 다른 안내 문구 |
| 필요 데이터 | 광고 목록 조회(페이징, 필터) |

- 정렬은 최신순 고정이다.
- 전시 기간 중 목록이 누적되므로 페이징으로 나눠 불러온다.
- 릴스는 영상 대신 썸네일 이미지를 받아 표시한다.
- 상세에서 돌아올 때 필터와 스크롤 위치를 유지한다.

## 4. 백엔드 요청 사항

| 기능 | 사용 화면 | 요청 | 응답에 필요한 값 |
| --- | --- | --- | --- |
| 템플릿 목록 | SC-03 | `user_id` | 템플릿 ID, 이름, 가게 설명, 메뉴 목록 |
| 템플릿 저장 | SC-03 | `user_id`, 이름, 가게 설명, 메뉴 목록 | 템플릿 ID |
| 대본 생성 요청 | SC-03 | `user_id`, 형식, 콘셉트, 가게 설명, 메뉴 목록 | 작업 ID |
| 대본 결과 조회 | SC-06 | 작업 ID | 상태, 장면 목록(장면 번호, 대상, 자막) |
| 재료 업로드 | SC-07 | `user_id`, 장면 번호, 메뉴 식별값, 파일 | 저장 경로 |
| 생성 요청 | SC-07 | `user_id`, 형식, 콘셉트, 재료 목록, 자막 목록 | 광고 ID, 작업 ID |
| 생성 상태 조회 | SC-07 | 작업 ID | 상태, 결과물 URL, 캡션, **진행 단계 정보** |
| 광고 목록 | SC-01, SC-09 | `user_id`, 형식, 게시 상태, 페이지 | 광고 ID, 형식, **썸네일 URL**, 제목, 게시 상태, 생성 시각 |
| 광고 상세 | SC-08 | 광고 ID | 결과물 URL 목록, 캡션, 게시 상태, 게시물 링크 |
| 캡션 수정 | SC-08 | 광고 ID, 캡션 | 성공 여부 |
| 게시 요청 | SC-08 | 광고 ID | 게시 상태, 게시물 링크 |
| 광고 삭제 | SC-08 | 광고 ID | 성공 여부 |

대본 생성 요청과 대본 결과 조회는 자막을 사용하는 릴스 템플릿에서만 호출한다. 그 외의 경우 생성 요청에 자막 목록이 포함되지 않는다.

굵게 표시한 세 가지가 특히 필요하다.

- **진행 단계 정보** — 없으면 생성 대기 화면에 무한 로딩만 표시된다. 단계 이름 또는 전체 단계 수와 현재 위치가 있으면 체감 대기를 줄일 수 있다.
- **썸네일 URL** — 목록에서 영상 원본을 불러오면 전시 후반에 목록이 무거워진다.
- **광고 삭제** — 관리 화면을 만들지 않으므로, 전시 중 잘못 만들어진 광고를 지울 수단이 필요하다. 지우지 못하면 홈의 최근 광고에 계속 노출된다.

결과물과 썸네일 URL은 브라우저에서 바로 열리는 형태로 제공되어야 한다.
