# 백엔드 요청사항

프론트가 API 를 붙이기 전에 백엔드에 부탁할 것. 답을 받으면 항목 옆에 결론을 적고 [백엔드_API.md](./백엔드_API.md)에 반영한다.

## 꼭 필요함 — 없으면 화면을 못 만든다

### 1. 응답 예시 (`data` 필드) — 대부분 받음 (2026-11-15)
결과 조회 · 보관함 · 홈 · 사진/영상 제출 예시가 OpenAPI 에 들어왔다. 남은 것: 릴스 썸네일 주소, 실패한 생성이 보관함에 어떻게 나오는지.

OpenAPI 에 모든 응답의 `data` 가 빈 객체로만 적혀 있다. 아래 API 의 실제 응답 JSON 을 하나씩 받고 싶다.

- `GET /api/ad-sessions/:sessionId` — 결과 화면. 카드뉴스 PNG 3장 · 릴스 MP4 · 썸네일 서명 URL, 캡션, 해시태그, 제목, 대표 메뉴가 어떤 필드로 오는지.
- `GET /api/archive` — 보관함 목록. 항목마다 썸네일 URL, 유형, 상태, 생성 일시, **상세를 열 때 쓸 `sessionId`** 가 오는지.
- `POST /api/ad-sessions/:sessionId/photos` · `/videos` — 1~5번째 제출 응답에 **다음 `currentRequest`** 가 오는지.
- `GET /api/home` — 쓸 수 있다면 응답 형태. OpenAPI 에는 이 API 가 없다.

### 2. ~~생성 실패 시 재시도 API~~ — 필요 없음
프론트가 실패하면 재시도 없이 홈으로 돌아가 다시 만들게 하기로 했다(2026-11-14).

### 3. 개발 주소 CORS 허용
지금은 `https://posttalk.vercel.app/` 하나뿐이다.

- 끝의 `/` 를 빼 주세요. 브라우저가 보내는 Origin 은 `https://posttalk.vercel.app` 이라 `/` 가 붙으면 일치하지 않을 수 있다.
- 추가: `http://localhost:5173`, Vercel 미리보기 주소(`https://*-posttalk*.vercel.app` 패턴 또는 목록).
- 실기기 테스트용 사내망 주소(`http://192.168.x.x:5173`)는 어렵다면 프론트가 Vite 프록시로 우회한다.

### 4. 영상 형식과 용량 — webm 받음 (2026-11-15). 용량 제한과 장면별 길이는 아직
- 브라우저 녹화(MediaRecorder)는 안드로이드 크롬에서 **webm**(VP8/VP9), iOS 사파리에서 mp4 로 저장된다. `video/webm` 을 받아서 릴스로 만들 수 있는지.
- `POST /api/uploads` 의 파일 크기 제한(413 기준)이 사진 · 영상 각각 얼마인지.
- 영상 한 개당 권장 길이(초). 결과가 약 13초인데 장면마다 몇 초를 찍게 할지 정해야 한다.

## 정해 주면 좋음

### 5. 실패 사유 문구
`failureReason` 이 사용자에게 그대로 보여 줄 한국어 문장인지, 오류 코드인지.
코드라면 코드 목록을 받아서 프론트가 문구로 바꾼다.

### 6. 진행률 응답 통일
카드뉴스와 릴스의 `stage` 값 목록을 받고 싶다(릴스 AI 는 `preparing` · `composing` · `uploading`).
단계별로 안내 문구를 다르게 보여주려 한다. `message` 를 그대로 써도 된다면 그것으로 충분하다.

### 7. 작업 공간 초기화
공용 기기라 체험이 끝나면 다음 사람에게 이전 결과가 보이면 안 된다.
프론트가 게스트 키를 새로 만들어 새 작업 공간을 여는 방식으로 처리하려 한다. 버려진 작업 공간이 계속 쌓여도 괜찮은지(정리 정책).

### 8. 보관함 상태값
게시 기능이 꺼져 있으면 모든 항목이 `draft` 인지. 생성에 실패한 항목도 보관함에 나오는지, 나온다면 상태가 무엇인지.

## 참고 — 문서 오타
- 배포 문서의 프론트 환경 변수 `NEXT_PUBLIC_API_BASE_URL` → 이 프론트는 Vite 라 `VITE_API_BASE_URL`.
- AI 서버 문서의 "프론트엔드는 AI 서버 주소, 내부 API 키, Supabase 서명 URL을 직접 사용" → "사용하지 않는다"로 보인다.
- `GET /api/health` 문서의 응답 예시(`{ status, service }`)와 OpenAPI 의 공통 형태(`{ success, message, data }`)가 다르다.
